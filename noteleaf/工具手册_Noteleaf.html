1 总览与设计哲学

Noteleaf 是云计算讲义（6 份自包含单文件 HTML，part1 至 part6）的生产框架。它不是「一键生成器」，而是一条人机分工的质检链：机器负责可复现的定位与核对，人负责裁决与创作。

原则落地方式
spec 单一真源六段顺序、能力归属、门禁名都写在 framework/spec/spec_v0.1.0.json；pipeline 不硬编码顺序，spec 漂移会被 FAIL 暴露
机器只定位，裁决归人所有检查输出「有/没有、过/不过、命中在哪一行」；教学结构检查永久 WARN 不 BLOCK，防「合规稿」KPI 游戏
append-only 台账素材台账、K1 工单、决策、门禁 run 记录全部只追加；同名冲突报错不覆盖，可回溯
显式意图写作前必须声明偏好（K3）与契约（intent_ga），缺项即拦（O2）；画像只收显式字段，不推断
断网不撒谎网络失败落「待取」工单而非「已取」；运行中文件被改由 doc_stable 暴露，不拿旧快照假装通过
纠错转检查同一个错只人工纠正一次，然后写成 lint 规则/脚本，违反即报错（参考 Lauren Tan / Claude Code 方法论）

3 pipeline_run.py — 六段编排主链（463 行）

位置 tools/lf/pipeline_run.py · 角色：端到端编排器，唯一入口

方法

  • 共享文档上下文：read_doc() 在 run 开头一次读入 HTML 的 bytes/text/md5，GATE/REVIEW/DELIVER 全程复用，不再反复读 3.5MB 大文件（token 与 IO 双省）。
  • doc_stable 收尾核对：run 结束时重算文件 md5，运行中被别处改动则报 CONTEXT FAIL，不拿旧快照假装通过。
  • 顺序来自 spec：pipeline_order(load_spec()) 决定段序；spec 里出现无执行器的段直接 FAIL 暴露漂移。
  • 进程内门禁：GATE 段直接调 check_chain.inspect(text=, digest=)，判据与 CLI 完全一致。
  • 讲义体例豁免：若门禁失败全来自 prose_fast 且只有厂商名命中（破折号/外链等为 0），判 PASS(讲义体例放行厂商)，命中数仍展示待作者复核。
  • 契约检查：REVIEW 段调 check_contracts()，对 contracts/ 下讲 ID 匹配的全部契约跑四要素 CHECK + 逻辑顺序 ORDER，结果进 full json。
  • 摘要/完整分离：--json 只打摘要；完整证据落 review/<讲ID>_pipeline_full.json；run 记录追加 .workbuddy/ledger/ledger.jsonl。

各段判定要点

段ok 判据备注
ASSET台账条数 > 0附供料 top5（user 置顶，其余 层优先级×评估分）与 M2 画像
ANCHOR写作规则九节部件齐备跨讲共用一份 ANCHOR_RULES.html
WRITE生成稿存在 + O2 前置 PASSprefs 缺项即拦
GATEcheck_chain 无 FAIL 门厂商名单独命中可豁免
REVIEW默认 pending 不算 FAIL--require-review 要求闭环；--require-rubric 要求 G2 无真 FAIL
DELIVER真外链 = 0XML 命名空间白名单放行

使用

python3 tools/lf/pipeline_run.py --lecture part4_20261125 \
    --html "CloudComputing/framework/part4_网络与接入_修订稿v3_20261125.html" \
    --json [--require-review] [--require-rubric] [--full-json] [--no-ledger]
# 退出码 0=PASS 1=FAIL

5 doc_read.py + asset_score.py — K2 解析与评估

5.1 doc_read.py（169 行）：文档解析层

照 OpenMAIC 解析层设计：按格式选解析器 → 保留结构 → 算内容指纹 → 统计可复核信号。只读、不评分、不入账。

  • 解析器路由：md/txt/html 直读（html 剥标签）；pdf/docx/pptx 走 marker_single（临时目录，不污染项目），读回 markdown + meta 的 block_counts（版面模型真值）。
  • 结构统计：优先 marker 的 SectionHeader/Table 计数；无版面模型时退回 markdown 正则（可手算复核），表数不猜（记 0）。
  • 相关性信号：主题词在正文出现次数（可手算），不用黑箱 embedding；coverage = 命中主题数/主题总数。主题词必须与 PREP 同一批，保证分母一致。
  • 输出：name/md5/chars/headings/tables/table_rows/formulas/hits/coverage/text_preview；--save 落 parsed.md 供后续引用。
python3 tools/lf/doc_read.py READ 论文.pdf --topics 拓扑 CLOS --mode fast [--save 目录]

5.2 asset_score.py（325 行）：五维评估卡

总分 = Σ(维度分×权重)，每维 0..1，计分透明可复核。

维度权重判据映射
源头层级0.30paper=1.0 / book_top=0.9 / vendor、course=0.85 / book=0.65 / blog=0.35 / video=0.3
机制完整度0.25high（给做法/步骤/数字）=1.0 / mid（名词+一句机制）=0.6 / low（只给名词）=0.3
可核对0.20yes=1.0 / partial=0.6 / no=0.2；机器读文件默认强制 no，人工显式 --cite yes 才承认（cite_basis 留痕）
时效0.15当年 1.0，每差一年 -0.12，下限 0.2
许可0.10cc/own/authorized=1.0 / commercial=0.35 / unknown=0.3
  • SCORE_FILE：读文件后用解析证据自动判机制（结构块≥5 且覆盖≥0.5 → high；≥2 或有覆盖 → mid；否则 low），不靠 snippet 猜。
  • FROM_TICKETS：K1→K2 打通。工单未入台账者自动粗打分（层映射：paper→L4 / vendor_card→L3 / textbook→L1），mechanism 用 snippet 启发式，cite 一律 no，回写工单 status=scored。--dry-run 只算不改。
  • sort_supply()：供料排序。user 自供条目置顶（原 K4 并入，唯一数据源是台账），其余按 层优先级×评估分 降序。
  • 条目不可变：同 name 冲突报错不覆盖。
python3 tools/lf/asset_score.py SCORE_FILE 论文.pdf --topics 拓扑 --layer L4 --src paper --recency 2022

6 prefs.py — K3 偏好矩阵（238 行）

位置 tools/lf/prefs.py · 数据 framework/prefs/<讲ID>_prefs.json

方法

  • 声明式偏好：四维（应用/原理/机制/架构）多选，写前声明；只影响供料排序与篇幅权重，不直接改正文。未声明默认「机制+原理」。

  • VERIFY 落实检查：在成品 HTML 找各选中维度的信号词（如机制=步骤/状态机/协议/字节），命中=有落点，未命中=WARN 待人工确认，不判好坏不阻塞。

8 check_chain.py — GATE 门禁编排器 / M1（378 行）

位置 tools/check_chain.py · 把散落在 skill 与 tools 的校验脚本收口成一条可复现 gate 链

方法

  • 资产类型自动探测：tex（目录/单章）/ html / pptx，按类型选门组合。
  • 门清单：tex_compile（编译/页数/Overfull，复用 check_chapter.sh）、redlines（破折号/厂商名/孤儿浮动体/图引用体例，A/B/C/D 计数）、html_delivery（外链/base64/标签/锚点）、deck_package（PPTX 包校验 13 项）、bundle_manifest（md5/图数/外链图/真外链，非 data: 图即 FAIL）、prose_fast（散文本兜底：破折号/数字双连/asciitilde/厂商/外链）。
  • 状态机 + 台账：每门输出 ok/fail/hits/evidence，全链终止码=有无 FAIL；每次 run 追加 .workbuddy/ledger/ledger.jsonl，--list 汇总历史门通过率（分母只算真有 gates 的 run，防虚高）。
  • 进程内入口：inspect(text=, digest=) 供 pipeline 复用，避免重复读 HTML；机检命中留 human_verify 占位，判定交人（五动作审稿）。

讲义体例与教材相反：讲义允许厂商名、保留出处外链；教材全禁。check_chain 的厂商/外链 FAIL 在讲义里属已知豁免项，由 pipeline GATE 段的 vendor_only 判定或作者复核处理。

10 rubric_check.py — G2 原子 rubric 评测器（253 行）

位置 tools/lf/rubric_check.py · 方法引自 PresentBench（arXiv 2603.07244）：二分判定 0/1 + 局部证据，不做模糊打分

解析器：CtxParser（标题栈）

HTML 小节通常不包裹 <section>，用「后出现即覆盖」的标题栈模拟：新标题弹出层级 ≥ 它的更细标题，段落记录归属标题链。li/td/th 文本记为 t=x 事件，供图引用核对但不参与空节/断言统计。img 走 handle_startendtag 配对（自闭合标签不漏）。

七个原子项（含实测校准记录）

项维度判据校准记录
R1结构/完整h2 节正文总长 ≥120 字初版按字典分组会继承过期文本误伤，改标题栈按文档顺序归属；h1 题与前导段不算节
R2结构/清晰h2≥2 且标题 ≥2 字初版要求 h2≥3 且标题 >8 字，「序章」2 字被误报，放宽
R3忠实度含数字（NUM 正则：ms/MB/%/倍/vCPU…）但无出处词（论文/官方/报告/[N]/据…）且无软化词（约/量级/左右）且段长 >40 → 导待回源清单核心产出：审稿人拿清单逐条对照素材，机器不判对错
R4视觉正文「图 N-M / 图 N.M」引用数 >0（双口径，li/td 里的引用也算）初版「无 alt 即 FAIL」被 13 张无 alt 拖垮，校准为零引用才 FAIL、缺 alt 降 WARN
R5清晰/术语含核心术语无定义句的段落数 < max(3, 段数/5)启发式，只 WARN 不计 FAIL
R6完整/覆盖h2≥2 视作主干完整—
R7完整/示例性每 h2 节有示例信号词（例如/案例/举个…）整页无这些词未必有错，降 WARN

--export-json 把待回源清单与无 alt 图导出，供独立审稿对照素材回源。与 check_chain 分工：红线机检抓格式（破折号/去公司化/外链），rubric 抓结构/忠实度（空节/无来源断言/图无引用）。

11 intent_ga.py — 意图契约 + G-A 四要素 + ORDER（369 行）

位置 tools/lf/intent_ga.py · 契约存 framework/contracts/<讲>_<节>.contract.json，模板 _TEMPLATE.contract.json

哲学

不评「这节浅不浅」，只回答可核对问题「声明的要素有没有落点、落在哪」。基准是意图契约不是模型印象；契约校验不过 → 整份不判，直接报无效。

契约字段纪律（validate_contract）

字段纪律
section_kindmechanism/transition/example/summary；变更必须 changelog 写 from/to/reason，无 reason 视为无依据变更
objectives必须「读者能+可观察动词」（解释/算出/区分/判断/复述/比较/识别）；「掌握/了解/熟悉/理解」一律拒收
known_terms_ref只许引用 vocab/ 封闭词表并锁版本（name@version），版本漂移即无效
required_elements按 kind 派生（mechanism=what/why/how/cost），可增不可减；减项必须 changelog 写理由
order_contractintuition_first / phenomenon_first / top_down 三选一
anchorsG2 事实锚（数字断言回源用）
order_anchors逻辑顺序锚（logic_order CONFIRM 写入）；字符串或 {anchor,source_ref} 对象均可

四要素 CHECK：双层判据

  • 第一层信号词（what=定义为/指的是/核心是…，why=因为/为了/局限…，how=步骤/监测/写入…，cost=代价/权衡/缺点/相比…）只说明「像是在讲这个要素」。
  • 第二层实质锚（可核对数字 / 具体术语 / 因果词 / 对比词 / 机制对象）必须信号窗内（前后 60 字、句内同窗，跨句会串味）至少命中一个。
  • 只有信号没有实质锚 = HOLLOW 空壳，不许升 PASS；元数据块（契约写进正文）先剥离，骗不过检查。

ORDER：逻辑顺序核对

只读 order_anchors（不回退 anchors，那是事实锚不是顺序锚）。返回每个锚词在正文的首次字符位置，报「逆序对」（后面的锚先出现）与缺失。判定交人，永久 WARN 不 BLOCK。

DIFF：契约变更审计

结构化字段 diff（不做整块文本对比）；section_kind / required_elements 变更高警示，无 changelog reason 判 INVALID。

python3 tools/lf/intent_ga.py CHECK contracts/part4_s12.contract.json 讲义.html --section-id s12 [--json]
python3 tools/lf/intent_ga.py ORDER contracts/part4_s12.contract.json 讲义.html --section-id s12
python3 tools/lf/intent_ga.py DIFF old.json new.json
python3 tools/lf/intent_ga.py --selfcheck

12 logic_order.py — 逻辑顺序工具（325 行，2026-11-25 新增）

位置 tools/lf/logic_order.py · 数据 framework/inputs/<part>/（manifest.json + concept_map.json + marker_out/）

机制主张

材料自带逻辑。工具从素材抽出概念顺序 → 评价候选哪个好 → 提案给作者 → 作者确认后写进契约 → 正文按契约组织 → ORDER 回读核对。机器只抽取与打分，裁决交人。

三段命令

命令方法
EXTRACT <inputs目录>抽素材 Markdown 标题行映射概念（一个标题可含多概念，按各自最早匹配位置排序，防泛词抢专词）；再抽 INTRODUCTION 段概念首提序；加权合并：章节骨架（作者明示逻辑）权重 2.0，引言序权重 1.0，按加权平均位置排序
PROPOSE ... --section 1.2 [--current a,b,c]生成候选（每份材料顺序补全 + 当前讲义顺序 + 先修拓扑序 Kahn），按三层打分排序去重输出
CONFIRM <contract> --order a,b,c --reason ...把作者选定顺序写进契约 order_anchors，version+1，changelog 记录理由与评分依据

打分判据（总分 = L1×0.4 + L2×0.4 + 覆盖×0.2）

层判据含义
L1 先修概念表 prereq 依赖满足率依赖概念必须排在被依赖者之前
L2 材料共识候选顺序对各素材概念顺序的一致率（共有序列对的 Kendall 式一致率）与权威材料叙述逻辑的吻合度
覆盖候选覆盖概念全集的比例别漏概念

素材与概念表（可调部件）

  • 素材真源：inputs/<part>/manifest.json + marker_out/（marker-pdf 2.2.0 抽取的 Markdown，章节骨架可信）。禁用 pdftotext：双栏混排会毁掉章节抽取（实测 FatTree/Jupiter 都翻车）。
  • 概念映射表 concept_map.json：{"概念名": {"pats": [英文章节/引言正则], "prereq": [先修概念]}}；下划线开头键是注释会被跳过。泛词要收紧（existing 会误命中 pre-existing，clos 裸词会抢 Fat-Tree 标题）。
  • 锚词必须与正文实际写法一致（正文写 Spine-Leaf 就别写 Leaf-Spine），否则 ORDER 报 missing。

15 配套写作方法论（两个 skill 的精华）

Noteleaf 的工具只负责「定位与核对」，真正决定讲义质量的是写作方法论。这套方法沉淀在两个 skill 里：cloud-lecture-writing（讲义逐节落地）与 book-production（全书体例与红线）。本章把两者的核心规则压缩进来，让独立包也能完整复用。

15.1 cloud-lecture-writing：讲义逐节落地

立场一句话：用户管怎么说，助手管对不对、能不能打开、能不能交接。助手不改文风、不重写、不机械归纳，只做三件事：修事实与逻辑、配图并内嵌、渲染进单文件并终检。

启动铁律（动手前按顺序，禁止凭记忆）

  1. 读项目记忆（MEMORY.md 的目录约定与发布通道），确认当前主写文件与顶层编号。
  2. 读进度文件与当天日志尾部，确认别的 agent 刚改过什么。
  3. 用脚本定位目标节的 h3 锚点、下一节锚点与当前图号分布；不要 grep 超长行 HTML（一行可能几 MB）。
  4. 目标文件按文件粒度备份到 /tmp；禁止整目录回滚。
  5. 风格判定读人文写作风格参考；禁止章首问句配额、句长、词频这类「AI 归纳」当判据。

事实核查（渲染前必做）

  • 草稿每个具体数字、时间、归属、机制结论，回一手源核对：经典论文原文、官方文档、标准文本。二手文章只做素材与图源，不做最终事实判据。
  • 只修三类问题：事实错、逻辑接不上、偷换主语。其余一字不改，保留路标句与产品例子。
  • 跨节断言（「5.4 节讲过一致性哈希」）必须去目标节 grep 关键词确认；零命中就换真锚或改述，不许凭印象。
  • 精确倍数、无出处的量化形容词，一手源没有就改成定性表述。

配图（现成图，逐张视觉校对，全部内嵌）

  • 只用现成权威图，不自绘。逐张打开看图内文字与结构，确认与正文一致；错图判废重来，不猜文件名。
  • 内嵌 base64 data URI，图注编号「图 N-M」，图下保留原始来源 URL。零外链单文件。
  • 图数按正文实际 URL 数，不按口述张数；不一致在交付说明里点明。

渲染与终检

  • 顺序固定：备份 → 构造新节 HTML → 单点替换旧节 → 补图插到指定锚点 → 按全文出现顺序重排本章图号 → 终检。
  • 图号重排用单次正则 + counter，禁止链式 re.subn（编号互相命中会产生「图 6.99」）。
  • 终检必须读回：图号连续、占位符零残留、外部依赖 0、标签配平；不靠脚本自证。

机械清理清单（对应 lecture_lint L1-L8，只做确定性替换，不动文风）

项规则
破折号—— 按语境改冒号/逗号/拆句；数字范围改「至」；裸 -- 删除
画外音图注删「OCR 已核验/据截图」；图注只留「图 N-M 说明（来源：X）」
空锚文本删「（去围观/看热议/看演进）」这类空链接；内容重要就并入正文，否则删
段首套话「值得注意的是/不难发现/综上所述」删除或改直陈，不动句子主体
空对举「不是 A，而是 B」只在明显套话时改；A/B 承载实质信息的保留
图引用每张图正文必须有「图 N-M」引用；图、图注、引用段同页
图大小像素宽 600-1000；PNG≤400KB / JPEG≤250KB；超限等比缩放
讲述顺序用 intent_ga ORDER 核对声明顺序与正文首次出现位置，机器只定位

就地改写与深度修订

  • 就地改写：只改现有句子让它更好读，禁比喻、反差、新框。设问/感叹/比喻/反差套话四类是硬命中判据。
  • 深度修订四规则：D1 术语首现必定义 / D2 一次讲完不重复 / D3 章首问题驱动不写路线图 / D4 内容密度让学生连贯读。用户标 TODO 常是举症状要你反推全文同类缺陷，不是逐条打补丁。

15.2 book-production：全书体例与红线

讲义精修七条硬门禁（进流水线之前逐条自检）

  1. 先读本地完整真源再动笔，禁止「去找教材」式空转；判断素材拿不拿得到先看本地再看网络。
  2. 按困难的因果链组织，不按产品目录铺开：先给困难，再给机制，再给代价；禁止节首提问盒子与对读者点名的话。
  3. 看厂商主页 = 看服务全貌与岗位知识，不是抠数字；按类扫产品地图，写前重扫不抄旧讲义。
  4. 素材质量 = 内容完整 + 读过内容，两件事都要；关键词命中数不证明素材可用。
  5. 图量充足且只用现成图不自绘；没有对得上的图就留图位说明，绝不硬塞，也不自己画。
  6. 目录与篇幅先给用户拍板再写正文。
  7. 写者不得自审，改写完成交独立审稿；凡「第 N 章讲了 X」必须去目标章 grep。

六条不可协商红线

  1. 交付格式：成果 = 单个自包含 HTML（内联 CSS/JS、图片 base64、零外部依赖）；禁 md 交付。
  2. 破折号：prose 中 ——/–/-- 一律禁用，数字范围写「10 至 20」；豁免 TikZ 连线、专名连接号、CSS 变量。
  3. 去公司化：教材正文禁厂商名；讲义体例相反（允许厂商名），两套稿件不互套。
  4. 忠实源材料：翻译与重构逐节覆盖不删内容；数据更新用蓝字块增补，原文保留。
  5. 插图路线 A：纯大模型生图复刻原图，零增零减；不装开源绘图工具、不写 DSL。
  6. 编辑不等于审稿：改动者不得自审；脚本只机械定位，判断交全新上下文五动作。

五动作审稿（由未参与改动者执行）

  1. 读者知识态轨迹：每节读完，读者应知道什么、能做什么，是否真的成立。
  2. 路标审计：核心结论/工程教训/选型决策句是否都有实质内容支撑。
  3. 引用读回：每个「第 N 章/节讲了 X」回目标处读原文核验。
  4. 归属与语气：数据、结论的归属是否准确，语气是否夸大。
  5. 硬错误：事实、数字、术语、图注逐条挑错。
分工边界：cloud-lecture-writing 管「一节怎么落地」，book-production 管「全书体例与红线」，Noteleaf 工具管「机器能定位的部分」。三者不互相复制明细：skill 是流程真源，工具是可执行判据，项目记忆是状态真源。

第 6 步的门禁命令组（全部在包根目录跑）：

# 四要素是否都写到（无 MISS）
python3 tools/lf/intent_ga.py CHECK contracts/<讲>_s<节号>.contract.json <讲义.html> --section-id s<节号>

# 讲述顺序是否与契约一致（无逆序、无缺失）
python3 tools/lf/intent_ga.py ORDER contracts/<讲>_s<节号>.contract.json <讲义.html> --section-id s<节号>

# 机械痕迹体检（FAIL 必须清零）
python3 tools/lf/lecture_lint.py <讲义.html>

# 结构与忠实度体检（FAIL 清零）
python3 tools/lf/rubric_check.py <讲义.html>

# 全链验证（含契约 CHECK/ORDER）
python3 tools/lf/pipeline_run.py --lecture <讲ID> --html <讲义.html> --json

17.2 轻量扩展一：加一条检查规则（纠错转检查）

同一个错只人工纠正一次，然后固化成规则，这是 Noteleaf 的核心方法论（参考 Lauren Tan / Claude Code）。

  • 机械痕迹（破折号、画外音、空锚文本、图引用这类可确定性定位的）→ 在 tools/lf/lecture_lint.py 加一项，编号顺延 L9、L10。
  • 结构 / 忠实度（标题、图、术语、示例这类原子项）→ 在 tools/lf/rubric_check.py 加一项，编号顺延 R8、R9。
  • 改完先跑 --selfcheck，确认没破坏既有检查再上真稿。
  • 原则不变：机器只定位、裁决归人；教学结构检查永久 WARN 不 BLOCK，防「合规稿」KPI 游戏。

17.3 轻量扩展二：加一个素材来源

  • tools/lf/k1_acquire.py 已内置四类来源：PAPERS（论文）/ VENDOR（厂商数字卡）/ TEXTBOOK（教材）/ ZHIHU（工程实践线索）。新来源照其中一类的工单写入模式加。
  • 论文标准知识点锚加在 framework/k1/paper_seeds.json 种子表。
  • 若要接 RAGFlow 发现层，需 framework/k1/ragflow.json（endpoint / token / kb）。本独立包不含此文件（含密钥），按 k1_acquire.py 内注释自行配置；缺失时工具自动跳过发现层并提示，不报错。

17.4 轻量扩展三：改流水线阶段或门禁

  • spec 是单一真源：CloudComputing/framework/spec/spec_v0.1.0.json。增删阶段、改能力归属、改门禁名，都只改这个文件。
  • pipeline_run.py 不硬编码段序，从 spec 读取；spec 里出现无执行器的段会被 FAIL 直接暴露，防漂移。
  • 改完先跑 python3 tools/lf/spec.py 自检（段序必须等于 ASSET→ANCHOR→WRITE→GATE→REVIEW→DELIVER）。
扩展的三条纪律
1. 加料不删史：台账、工单、决策全部 append-only，同名冲突报错不覆盖，可回溯。
2. 改规则带版本：词表 / 契约变更必须 version+1 并在 changelog 写理由。
3. 机器不裁决：所有扩展加的都是「可定位的检查」，不是「自动改写」；好坏判断永远归人。

19 排错表

症状原因与查法
ORDER 报 missing锚词与正文实际写法不一致（如 Leaf-Spine vs Spine-Leaf）；grep 正文确认写法后改契约
EXTRACT 概念顺序乱概念表泛词误命中（existing/clos 裸词），收紧 pats；确认素材是 marker 抽的而非 pdftotext（双栏混排）
pipeline WRITE 段 prefs FAILprefs/<讲ID>_prefs.json 缺失或维度非法；按 fix 命令声明
构建脚本 old_string 不匹配前序替换（如破折号→逗号）改了文本；按替换后文本精确匹配，或调整步骤顺序
lint 报跨标签「——」但原文没有剥标签时若用空串替换会把相邻单字「—」拼成「——」；确认用空格替换（已修）
图号重排出现「图 6.99」链式 re.subn 编号互相命中；必须单次正则 + counter 函数
RAGFlow 发现层全是无关文档全局 Top-N 被高频类目淹没；确认走了分组配额 + 标题弱重叠门禁（已内置）
iCloud 写入被拒TCC 限制：只用 ditto，不用 ls/python 直写；mdfind/md5 可验证
pipeline CONTEXT FAIL运行中文件被别处改动（doc_stable 检出）；重跑或查并行 agent
selfcheck 失败改完工具先跑 --selfcheck 再上真稿；selfcheck 用临时目录不污染数据

附：设计原则红线（速记）

  • 机器只定位，裁决归人；教学结构检查永久 WARN 不 BLOCK。
  • 纠错转检查：同一个错只纠正一次，然后写成 lint/脚本。
  • 确定性机制 > 提示词：能脚本判定的不靠文案提醒。
  • 验证优先：每个工具带 selfcheck 与可核对数字（md5 / FAIL 计数 / 覆盖率）。
  • 讲义体例与教材相反：讲义允许厂商名、保留出处外链与路标句；教材全禁。两套稿件不互套。
  • iCloud 写入只用 ditto；生成脚本放 /tmp；交付物单文件自包含 HTML；禁 md 交付。
